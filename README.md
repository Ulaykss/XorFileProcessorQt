# XOR File Processor — Qt/C++

Готовое GUI-приложение на Qt Widgets для потоковой модификации бинарных файлов операцией XOR с 8-байтным ключом. Проект можно открыть в Qt Creator как CMake-проект или как qmake-проект через `XorFileProcessor.pro`.

## Что реализовано

- выбор входного каталога;
- маски файлов, например `*.txt;*.bin`;
- опциональное удаление успешно обработанного входного файла;
- выбор каталога назначения;
- поведение при конфликте имени: перезапись или добавление счетчика (`file_1.bin`, `file_2.bin`, ...);
- 8-байтный ключ в формате 16 hex-символов, например `1234567890ABCDEF`;
- однократный запуск или периодический опрос входного каталога;
- пауза, продолжение и остановка;
- работа с файлами >10 GB без загрузки файла целиком в память;
- обработка в отдельном `QThread`, поэтому GUI не блокируется во время обработки;
- временный `.part`-файл и финализация через rename;
- корректное прекращение обработки при закрытии окна;
- защита от повторной обработки одного и того же файла в режиме периодического опроса.

## Семантика XOR

Ключ из 16 hex-символов трактуется как 8 байт в указанном пользователем порядке. Например:

`1234567890ABCDEF` → байты `12 34 56 78 90 AB CD EF`.

Ключ циклически повторяется по содержимому файла:

`output[i] = input[i] XOR key[i % 8]`.

Это эквивалентно XOR каждого 8-байтного блока с одним и тем же 8-байтным значением; для последнего неполного блока применяется соответствующая начальная часть ключа.

## Сборка под Windows + MinGW

Требуется Qt 5 или Qt 6 с модулем Widgets и CMake.

Пример для Qt 6 + MinGW:

```bat
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_PREFIX_PATH=C:\Qt\6.8.3\mingw_64
cmake --build build --config Release
```

После сборки исполняемый файл находится в `build\XorFileProcessor.exe`.

Чтобы приложение запускалось на чистой Windows-машине, рядом с EXE нужно развернуть Qt DLL. Для стандартной поставки Qt используйте `windeployqt.exe` из каталога Qt:

```bat
C:\Qt\6.8.3\mingw_64\bin\windeployqt.exe build\XorFileProcessor.exe
```

## Важные инженерные решения

### Большие файлы
Файл читается и записывается блоками по 8 MiB. В памяти одновременно находится только текущий блок, поэтому размер файла практически не влияет на потребление RAM.

### GUI не зависает
Весь тяжелый I/O находится в объекте `FileProcessor`, перенесенном в отдельный поток `QThread`. В GUI-поток приходят только сигналы прогресса и статуса.

### Пауза и остановка
Остановка и пауза кооперативные: состояние проверяется между блоками и во время записи. Остановка не обрывает открытый файл посередине блока; незавершенный временный `.part`-файл удаляется.

### Корректное завершение
Результат сначала создается как временный файл в каталоге назначения. После успешной обработки временный файл перемещается в итоговое имя. Это снижает риск оставить пользователю поврежденный итоговый файл при ошибке I/O.

### Периодический режим
Уже обработанный файл не запускается повторно на каждом цикле таймера. Отслеживается комбинация пути, размера и времени изменения. Если существующий входной файл был изменен, его новая версия может быть обработана снова.

## Проверка перед отправкой работодателю

Рекомендуется прогнать минимум следующие сценарии:

1. Небольшой `.bin` и ручная проверка первых байтов XOR.
2. Файл 10–20 GB: проверить RAM и отсутствие зависания интерфейса.
3. Пауза/продолжение во время обработки большого файла.
4. Остановка во время записи и отсутствие неполного итогового файла.
5. Конфликт имен с режимом перезаписи и режимом счетчика.
6. Периодический режим: файл появляется в каталоге после старта и обрабатывается без перезапуска программы.
7. Завершение приложения во время обработки.
8. Случайный файл с размером, не кратным 8 байтам.
